# claudekei — contributor notes

Claude Code plugin (plugin name `claudekei`), port of oh-my-openkei (OpenCode). No build
step and no dependencies: agents/skills are Markdown, hooks are plain Node ESM.

## Layout

- `.claude-plugin/plugin.json` — plugin manifest; `.claude-plugin/marketplace.json` — this repo is also its own marketplace (`source: "./"`).
- `settings.json` — makes `orchestrator` the default main-thread agent.
- `agents/*.md` — 4 primary agents + 7 specialists. Specialists are referenced as `claudekei:<name>`.
- `skills/` — bundled skills. `skills/{orchestrate,plan,sprint,analyze}` are GENERATED by `scripts/sync-modes.mjs` from the primary agents; never edit them by hand.
- `hooks/hooks.json` → `hooks/claudekei.mjs` (single entry) → `hooks/lib/{handlers,sessions,store,config,project-settings,user-config}.mjs`.
  - `user-config.mjs` reads the optional `claudekei.jsonc` (user + project); `PreToolUse` on `Agent` fills `model`/`effort` from it via `updatedInput`.
  - `project-settings.mjs` writes `agent` for `/claudekei:agent` into the project's `.claude/settings.local.json`, or `~/.claude/settings.json` when `claudekei.jsonc` sets `"agentScope": "global"` (`skills/agent/SKILL.md` is only the fallback when the hook does not run). It never sets `model`/`effortLevel`: the desktop app passes explicit `--model`/`--effort`, which beat settings. It only removes unchanged values v0.4.0 wrote (tracked by `store.mjs`).
  - `sessions.mjs` is pure logic (aliases, eviction, rendering, delegation rules).
  - `store.mjs` owns the per-session JSON state under `${CLAUDE_PLUGIN_DATA}/sessions/` with a mkdir lock (parallel hooks).
- `claudekei.jsonc` — copyable config template for users; `test/user-config.test.mjs` fails if it drifts from `agents/*.md` defaults.
- `.mcp.json` — bundled MCP servers (tools are `mcp__plugin_claudekei_<server>__*`).

## Workflow

1. Edit agents/hooks/skills. If you change a primary agent, run `npm run sync:modes`.
2. Update `README.md`, `README.vi.md`, and `docs/` when behaviour or config changes.
3. `npm run check` (sync check + `node --test` + `claude plugin validate .`).
4. Live test: `claude --plugin-dir . -p "..."` in a scratch project.
5. Release: `scripts/release.sh [patch|minor|major|X.Y.Z] [-m msg]` bumps `plugin.json` + `package.json`, runs checks, commits, tags `vX.Y.Z`, pushes, and updates the local plugin (`--dry-run` stops before commit).

## Conventions

- Hooks must fail open (never exit non-zero, never block on errors) and stay dependency-free.
- Hook payload shapes are documented by the fixtures in `test/hooks.test.mjs`; keep them in sync with real Claude Code output when changing handlers.
- Single quotes, 2-space indent, English code comments.
